## 一、RPD 理论要点（审视所用的框架）

Recognition-Primed Decision（识别启动决策），Gary Klein 在自然决策研究（NDM）中提出，
刻画专家在时间压力、信息不全、目标模糊环境下的高质量判断：

| 变体 | 决策方式 | 典型场景 |
|---|---|---|
| RPD-1 简单匹配 | 情境熟悉，模式直接对应行动 | 老消防员瞬间判断方案 |
| RPD-2 特征匹配+情节构建 | 线索不全，拼线索"讲故事"补全情境 | 线索缺失时构建解释 |
| RPD-3 心理模拟评估 | 先推演行动后果再执行 | 脑内"放电影"预判可行性 |

**核心特征**：不做多方案并排比较——模式识别先锁定一个最合理方案，心理模拟检验，失败
换下一个（区别于理性决策模型的期望效用比选）。**在 agent 领域的常见转译**：经验库=模式库
（相似度匹配）、计划模块=心理模拟（沙盘推演）、Team-RPD=多 agent 共享线索（R-CAST 等）。

## 三、同构映射（skill 决策机制 vs RPD）

| RPD 机制 | skill 对应物 | 吻合度 |
|---|---|---|
| 经验库=模式库，新任务先相似度匹配 | **分型问题池 A~G**（00 分册 §3：建模单件/场景/材质灯光/出图/动画/导出/改场景——先识别分型，每型预制问项与默认值） | 高度吻合 |
| RPD-1 熟悉情境直接行动（System 1） | **直通档**（查询/单步修改/规格已足 → 不问直接执行） | 高度吻合 |
| RPD-2 拼合线索构建解释 | **快速档**（1 轮 ≤4 问带默认值补全线索 → PRD 卡片 = 情境构建的成文化产物） | 吻合 |
| **单方案承诺 + 失败回退**（RPD 区别于理性比选的核心特征） | **推倒重来通道**（13 分册 §6：blockout 不合格回卡 1、禁止带病进细节）；简单任务单路径直行 | 吻合 |
| **（对照）多方案生成-择优** | **M6 多路径搜索**（12 分册 §4：复杂任务生成 3 套实质不同方案，串行"建→截(320×200 级)→评"、批评者角色对比诊断择优——串行系单 Blender 实例平台约束，非认知架构选择） | **有意偏离 ④**（专家不显式枚举多方案；详见 §四） |
| RPD-3 心理模拟评估 | 阶段 checkpoint（EEVEE 快渲 + report 投影）——见偏离 ② | 结构吻合、载体外置 |
| 快/慢思考分层（System 1/2） | 直通/快速 ≈ System 1；完整/无限挡 ≈ System 2（**显式化为档位**。注：快慢分层指交互强度与流程量，不指承诺机制——承诺机制见上两行，分属两层抽象） | 吻合且显式化 |
| 复用阶梯（经验库物化） | nodes/ 节点组 → fragments/ 积木 → 记忆指针 → 从基元写起 | 吻合（L1/L2 自 v2.2.0 起有货） |

## 四、有意偏离（四处，各附 WHY；"档位显式化"已并入 ①）

| # | RPD 原貌 | skill 的做法 | WHY（设计立场） |
|---|---|---|---|
| ① | 专家自动完成情境识别与定义（识别启动在脑内完成） | **情境建模权外置给用户**——反问循环 + PRD 卡片 + 用户确认闸才是识别过程的基质，**用户是识别过程的共同作者**；档位选择亦然（"档位是用户的选项，不是 AI 暗自决定"，AI 只做推荐附理由） | LLM agent 的"直觉"可靠性不如果断的人类专家；情境建模错误需要用户共同作者兜底。这正是 PRD 卡片/质量门体系的存在理由 |
| ② | RPD-3 在脑内"放电影" | **心理模拟外置到 Blender 实机**——快渲 checkpoint + report JSON 投影（C5 公理：状态归 Blender、模型只见 report） | LLM 的脑内推演会产生无凭据的乐观；实机沙盘 + 机验 report 是"模拟"的可靠化转译 |
| ③ | 专家靠经验直觉直接识别收敛 | **无限挡用五域清单结构化收敛** + 默认值翻牌制 | 承认 agent 经验不足，用清单兜底直觉——全套设计里最"反 RPD"的一处，同为有意（不信任未经结构化的直觉） |
| ④ | 专家不显式枚举多方案（识别后单方案推进+失败换下一个） | **复杂任务显式生成-择优**——M6 多路径搜索生成 3 套实质不同方案、批评者角色对比诊断（12 分册 §4，串行为平台约束） | 复杂任务下 LLM 的首选方案失败率高于人类专家的直觉首选；显式枚举+批评者择优是"失败换下一个"的强化前移——把"换下一个"从失败后提到生成时 |

Team-RPD / 多 agent 协作（R-CAST 路线）：无对应——本 skill 为单 agent + 单 Blender 实例
（官方单连接约束，出处 references/09 §4A"Only one MCP server instance can connect at a time"），
不适用。

## 五、结论

1. **无漂移**：skill 从未宣称遵循 RPD（入库前字面零命中），不存在"名为 RPD 的设计被改坏"的问题。
2. **两个体制、同一条公理**：简单任务走 RPD 式单方案承诺+失败回退；复杂任务走 M6 生成-择优。
   两者的存在由同一条设计公理解释——**LLM agent ≠ 人类专家，凡依赖专家内在能力（直觉/
   脑内模拟/经验识别/单次即中）之处，一律外置为可治理、可机验的结构**（用户共同作者/
   实机沙盘/结构化清单/显式枚举）。
3. **偏离即立场**：四处偏离（情境建模权外置〔含档位显式化〕 / 实机沙盘 / 清单兜底 / 生成-择优）
   全部可追溯到上述公理。这使 skill 成为 RPD 的"agent 化变体"而非 RPD 的实现。
4. **引用建议**：若在 DSH 侧论文/报告中引用，建议表述为"该 skill 的决策机制与 RPD 存在
   结构同构（模式匹配分型、简单任务单方案回退、快慢分层），但在情境建模权、模拟载体、
   收敛机制、方案生成四处有意偏离（复杂任务另设 M6 三方案串行择优），以适配 LLM agent
   的可靠性边界"。
