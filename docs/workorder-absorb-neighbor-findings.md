### B. references/09 增补两条（插在 §4 卡死恢复 SOP 之后）
1. **故障模式：僵尸 blender-mcp.exe 进程**
   - 症状：莫名弹窗、连接行为诡异、命令队列时好时坏；
   - 排查：`netstat -ano | findstr 9876` 应**只见一条** `127.0.0.1:9876 LISTENING`——
     多条即僵尸；任务管理器清点 blender-mcp.exe 数量；
   - 处置：多余的 blender-mcp.exe 进程结束之（确认不是正在服务的那个）；Blender 侧
     Stop→Start MCP Server 重置；
   - 预防：用完即 Stop / 关 Blender；不同会话共用一台 Blender 时先对齐"谁在连"。
2. **安全模式通道真相（重要修正）**
   - 修正表述："只有用户能关 Safe Mode" 仅对 **ZCode 正式注册的那条 MCP 通道**成立；
   - 真相：任何本地进程都能以 `BLENDER_MCP_SAFE_MODE=0` 自起一条 stdio 连接（实测案例：
     隔壁对话的 `tank_preview_inproc.py` 为 `import gpu` 离屏渲染另起了 SAFE_MODE=0 子进程）；
   - 落成"高级模式"条目而非禁令：适用=临时需要 gpu 模块等白名单外能力；纪律=仅独立子进程、
     代码先审核、用完即弃、绝不触碰用户文件；同时警示：这条通道也是他方攻击者的同等通道，
     第 4 层操作兜底（保存权在用户）因此不可省略。
