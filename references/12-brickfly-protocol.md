# 12 力大砖飞执行契约（M1~M12 协议条款）

> 上游设计文档：`docs/architecture-brickfly-v3.md`（why）。本分册是执行契约（how），
> 条款均带平台修正标记【修】——修正依据为本会话实测，与架构原文冲突处以本分册为准。
> 平级分册：00（需求澄清=方案层入口）、02/03/09（M7 弹药）、11（部署与 GPU 配置）。

## §1 骨架五段式（M1/M2/M3）【已裁定①：强制】

凡**新建/修改/删除场景数据**的 execute_blender_code 一律走五段式（模板
`scripts/brickfly_skeleton.py`，可直接粘贴改参数）：

```
① 参数区   PREFIX + PARAMS（PRD 卡片确认后由此实例化，见 §6 映射表）
② 幂等清理 reset_prefix(PREFIX)——只动 PREFIX_*，跑十遍状态一致
③ helper   find_node(按 node.type 查, 中文UI安全) / set_input(候选名列表) / count_tris
④ 建模段   实际构建逻辑；注释顶部引用相关教训编号（BMCP-ERR-NNN）
⑤ report   print(json.dumps(report)) —— 唯一出口
```

- 纯只读检查脚本豁免 ①②④，但**必须**有 ⑤；
- report 规范【修5】：`json.dumps` 默认 ensure_ascii（GBK 控制台禁裸中文）；float
  round 4 位；字段精简（name/loc/dims/tris/warnings/err）；
- **下一轮推理必须引用 report JSON 描述场景，禁止凭记忆**（C5 公理）；
- 30s 纪律：单次脚本 Blender 侧工作量 ≤20s（02 分册同款）。

## §2 四阶段隔离（M4）

复杂任务拆四阶段，**几何 → 材质 → 构图 → 灯光**：
- **「几何」阶段内部遵循 13 分册的七阶段工艺管线**（blockout→…→细节，含停手判据与偏离机制）；
- 每阶段结束 = checkpoint：report + 快渲判据（§3），达标才进下一阶段；
- 阶段失败只回滚本阶段（重跑该阶段 PREFIX 代码），不返工上游；
- **阶段依赖是单向的【BMCP-ERR-006，实测】**：重跑任一上游阶段后，必须按序重跑其下游
  全部阶段——实测只重跑几何，13 个物体的材质指派**全部静默丢失**（物体数/前缀/面数全
  达标不报错，只有 material_slots 归零）。探针判据：重跑后检查 `len(obj.material_slots) > 0`；
  骨架模板的阶段依赖戳（`bf_stage_digest` 自定义属性）用于下游启动时校验上游版本；
- 下游只引用上游 report JSON，永不凭记忆假设场景；
- 简单任务（单物体、无材质要求）可跳过阶段直接走执行环。

## §3 三级视觉反馈（M5）【修2/修3】

| 级别 | 手段 | 时机 | 本机要点 |
|---|---|---|---|
| 眼快扫 | 固化视角的视口截图 | 每轮小步 | 【修2】`get_viewport_screenshot` 跟随用户视口（非确定性）——截图前置代码：视口切材质预览 + `view_perspective='CAMERA'` + `view_matrix=cam.matrix_world.inverted()`；或走 GPUOffScreen 子进程（SAFE_MODE=0，按 09§4B 高级模式纪律）。**实看义务（U-03 同族）**：截图返回后必须实际扫描并描述所见（主体/问题点），截而不看 = 没截；视觉通道不可达时按 00 分册 R1 降级条款标 △。**全流程视觉编排见 14 分册**（开场识别/实时闭环/展示义务） |
| 快渲 | EEVEE 16 采样 960×540 | 阶段 checkpoint | `taa_render_samples=16`；渲染后 `bpy.data.images.load` 回读验证（禁 open()）；**产出图同样须实看**（文件读取工具打开 PNG 或截图通道），质量判断禁止凭想象（U-03 同族）；视觉通道不可达时按 00 分册 R1 降级条款标 △ |
| 精渲 | Cycles | 里程碑/用户验收 | 【修3+实测判据】本机无 GPU：**三角面 <5 万且 ≤720p/64spp 时 CPU Cycles 通常 <30s**（实测 1280×720/16spp/672tris=3.96s、EEVEE 960×540/16spp=0.69s）——以首次冒烟的实测耗时为准记入 report，勿按"无 GPU"一刀切推给用户；场景更大才交用户手动或分步轮询；根治=按 11 分册配 GPU |

## §4 多路径搜索（M6）【修1：串行】

触发门槛：任务 >2 阶段 / 含有机形体 / 用户要求"好看"。
- 生成 3 套实质不同的方案（不同基元策略/修改器组合/拓扑思路）；
- 【修1】**串行**执行：单 Blender 实例=单命令队列，不存在并行——PREFIX 隔离逐个
  "建→截(320×200 级)→评"；批评者角色对比诊断择优；
- 落选方案的可用代码段归档 fragments/（按其 README 元数据格式）；
- 简单任务单路径直行；落选方案截图当轮丢弃（M11）。

## §5 API 防幻觉（M7）

三层防线（弹药在 02/03/09 分册）：
1. **禁令**：交互式 op（loopcut_slide 等）、UI 依赖 op（screen.*/view3d.*）、已废弃 API
   （use_auto_smooth、3.x dict override；`do_unlink` 参数 5.2.1 实测**仍可用**非禁令）、安全模式白名单外写法
   （lambda/class/别名 import/动态 getattr/dunder/方法赋短变量/裸 next()/numpy/bpy_extras）；
2. **候选名 helper**：socket 赋值一律 `set_input(node, [候选名...], v)`；节点查找一律
   `find_node(nodes, 'BSDF_PRINCIPLED')`（中文 UI 默认名本地化，禁按英文名 get）；
3. **诚实原则**：不确定的 API 写 `todo` 标记交人工确认，禁止编造。

## §6 PRD 卡片 × 骨架参数区映射【已裁定④】

与 00 分册的需求澄清环对接：**卡片确认 = 方案批准 = 参数区实例化，一份两用**。

| PRD 卡片字段 | 骨架落点 |
|---|---|
| ① 目标一句话+参考 | ④建模段的方案注释头 |
| ② 交付物清单 | ⑤report 字段集 + 输出配置（分辨率/格式/路径） |
| ③ 非目标 | ④段内"不做"注释（防顺手加戏） |
| ④ 技术约束（PREFIX/单位/面数预算） | ①参数区 PREFIX、单位换算、面数断言 |
| ⑤ 验收标准 Given/When/Then | report 字段判据 + checkpoint 快渲判据（执行环的退出条件） |
| ⑥ 边界与假设 | ①参数区默认值注释（显式假设，不脑补） |
| ⑦ 反查雷区 | ④段的专项自检代码 |

直通档任务（规格已足/小改动）可跳过 PRD 卡片，直接填骨架参数区。

## §8 组件复用阶梯（M9）【已裁定②】

写建模逻辑前按固定优先级：
1. `nodes/` 参数化节点组（.py 重建脚本；调参数即用）
2. `fragments/` 代码积木（粘贴改参数）
3. 记忆组件指针 → 按 path 取文件 → **执行前验证文件存在**（失败按无此积木处理并修正指针）
4. 全无 → 从基元写起，完成后按格式归档 fragments/

组件指针条目格式：`[组件名] [路径] [一句话用途] [验证命令]`。
