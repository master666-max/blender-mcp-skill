# 14 视觉工作流（多模态深度融合）

> 定位：**视觉感知的全流程编排册**。设计前提（U-04 翻转）：执行模型具备**原生多模态
> 能力**——视觉不是附加的验收步骤，而是贯穿"开场识别→过程修正→思考→成品展示→
> 知识库检索"的一等感知通道，**默认开启**。
> 分工（避免双真相源）：本册是全流程**编排**与 §2/§4/§5 新增义务的权威定义处；
> 00（R1/R5 判据与宣告行）、12 §3（截图技术实现）、13（卡 0 参考实看/§7 停手判据）
> 各自保留域内权威，以"摘要+明锚"互指。

## §1 感知前提与自检（每次会话，并入 SKILL §0 第 3 步）

1. **前提翻转**：视觉通道默认开启。开场固化视角截图一次并**实看**——同时完成三件事：
   确认多模态通道可用；获得场景第一印象；为后续任何视觉判断建立基线。
2. **两态区分（F-74 承接）**：有图像能力但读不到（链路故障→走 SKILL §6 排障）vs
   无图像能力（环境降级→声明后降级运行）。两种都**不得假称合格**。
3. **降级是异常路径，不是平行模式**（U-04 定位）：通道不可用时须 (a) 开场即告知用户
   "视觉通道不可用，质量保障降级，建议切换多模态路由"；(b) 后续所有宣告行标 △；
   (c) 高视觉依赖任务（调色/构图/风格匹配）在降级下不建议执行，与用户协商。

## §2 开场识别（进入任何编辑前的感知层）

1. **场景视觉盘点**：任何编辑任务开始前，固化视角截图并实看，产出"**所见清单**"入
   report——有什么物体、光照氛围、风格基线、可疑点。get_scene_info 回答"有什么物体"，
   视觉盘点回答"**看起来是什么样**"——两者缺一不可，后者是 U-03 的开场形态；
2. **参考规格提取**：用户提供参考图（对话内图或文件路径）→ 必须实看，并把**视觉规格**
   写进 PRD 卡片——剪影/配色/材质性格/氛围/构图。只说"已看参考图"不算看过：
   看过的证据是卡片里的具体描述；
3. **意图确认闭环**：开工前向用户复述"我看到的/我理解的"（场景盘点摘要 + 目标视觉
   描述 + 提取的规格），用户纠正后再进入执行——开场消灭理解偏差，比返工便宜一个量级。

## §3 过程实时闭环（改→看→修，"看"不是一次性动作）

- 标准循环细化为：**改 → 截/渲 → 看 →（不满意→定位问题→再改）→ 复看确认 → 汇报**；
- **修正指令必须引用所见**（"左柱比参考矮一截/高光爆了/贴图接缝可见"）——视觉推理
  进 report 与对话，禁止无归因的"再调调"；
- checkpoint 门判据按 00 分册分工：**G1/G2 为目验门**（看图 + 视觉修正清单，PASS 含
  "所见无待修项"）；**G3/G4 为机验门**（G3=体检 report、G4=导出回读，照 00 机验判据，
  不以看图替代）——见 F-117 勘误；
- 技术实现（固化视角/截图/快渲）按 12 分册 §3，本册不重复。

## §4 成品检验与展示（交付的展示义务，U-04 新增）

- R1 双层判据照旧（00 权威：存在性层 + 视觉层）；
- **成品展示义务**：交付说明必须**内嵌最终渲染图**（图随交付走，用户不应自己打开文件
  才能看见成果）+ 已看过的视觉描述（所见要点，不是"已完成"三个字）；
- 有参考图的任务**对照展示**：参考 vs 成果并列呈现，并自述差异点与遗留妥协；
- 宣告行 `R1✓(路径;视觉✓)` 照旧（00 权威）。

## §5 知识库与资产检索的视觉化

1. **资产库检索实看**（06 分册五库通用；F-113 补出路；F-133 按真机实测改写通道事实）：
   search 结果的**缩略图/预览必须实看后再选择**——外观匹配是选择依据，名称/标签只是初筛。
   **通道事实（v2.4.0 真机实测，与上游 2.0.0 源码同构）**：五库中仅 Sketchfab 有回图工具
   （需 API Key）；PolyHaven（免 Key 默认推荐）search 返回的**文本只含 名称/ID/类型/分类/
   下载数，不含任何 URL**（server 格式化时丢弃 thumbnail_url，URL 从未到达模型）——
   故"把缩略图 URL 落盘后实看"的路径**在 MCP 通道内不成立**（Blender 内 safe mode 亦封
   网络与文件读取）。**可行路径**：先下载低分辨率资产、进场景渲染后实看再决定取舍；
   该路径也不可用时如实告知用户"当前无法实看资产外观"并按 △ 口径处理，
   **不得按名称/标签选完就声称已实看**；
2. **组件预览约定**：fragments/nodes 新增组件**必须附渲染预览图**（存量组件在下一次
   触碰时补，不追溯）；使用组件前实看预览，判断视觉适用性——复用阶梯的每一级都该
   "看得到长什么样"；
3. **worked example 视觉引用**：docs 案例须引用其渲染产物；检索到相似历史案例时
   看图判断可迁移性，而不是只看文字描述。

## §6 降级执行（前提不成立时）

△ 语义与格式照 00 R1 权威定义（`R1△(视觉未核验:<原因>)`，永不静默省略）。本册补充
定位：**视觉开启是默认，降级是异常**。降级会话的特征：(a) 开场声明；(b) 宣告行带 △；
(c) 高视觉依赖工序（调色审核/构图评价/风格匹配）不建议在降级下执行，与用户协商
改期或切换路由——**用降级模式做视觉密集任务，等于承诺无法兑现的质量**。
