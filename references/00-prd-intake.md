# 00 需求澄清（PRD 反问循环）

> 定位：建模任务的**方案层入口**——一句话指代不清的任务在这里规格化，产出 PRD 卡片；
> 用户确认卡片 = 方案批准 = 骨架参数区实例化（12 分册 §6 映射表），一份两用。
> 素材来源：spec-kit /clarify 配额制、外包 commission brief 字段惯例（Lemon Sky/Polycount/
> r-blender）、superpowers 分级思想（P0 调研 2026-09-12）。

## 1. 触发门槛（四档；先查后问）

**提问前先扫上下文**（get_scene_info / 对话历史）——用户已说过的、场景里能查到的字段
标"已从上下文推断"，绝不问。然后分档：

| 档 | 触发 | 行为 |
|---|---|---|
| **直通档** | 查询/体检类（"面数多少"）；单步修改（"把立方体变红"）；规格已足（有参考图/明确数值/明确风格） | 不问，直接按 SKILL.md §4 工作循环执行 |
| **快速档** | 默认适用于一切"做个/建个/渲染个"类一句话任务 | **1 轮 ≤4 问**（全带默认值，可回"按默认"整体跳过）→ 出卡片 → 确认 → 执行 |
| **完整档** | 多物体场景 / 用户主动展开 / 回答出现自相矛盾 | 2~3 轮（硬上限 3），后续轮只问前轮暴露的矛盾与新依赖 |
| **无限循环挡** | 用户明说（"多问我几轮/边聊边细化"）；场景级任务 AI 可建议（拒绝即回落完整档）；任何档位说"继续问"升级 | **轮次无上限，退出权在用户**：每轮 ≤4 问+只问新信息严禁重问；PRD 卡片草稿逐轮演进展示（"本轮敲定 X/Y/Z，还剩 N 个开放点"）；"开工"通道永久内嵌，说"开工/就这样/按这个来"立即冻结卡片进入执行 |

### 无限挡深度协议（v1.9.4 落地——穷尽细节的结构化骨架）

无限挡的收敛**不靠 agent 觉得"差不多了"**，靠**域清单覆盖度**。五个细节域，按序推进，
每域问透（用户连续两答"没有了"）才进下一域：

| 域 | 覆盖内容 | 典型问题下沉示例（以枪械为例） |
|---|---|---|
| ① 物理域 | 整体尺寸/重量/材质/表面处理/分色 | 全长之外：枪管长占全长比例？表面是哑光还是磷化？双色分界在哪条线？ |
| ② 功能域 | 用途场景/可动件/交互件/附件接口 | 弹匣可换吗？枪托可伸缩吗？导轨要不要？挂绳环在哪侧？ |
| ③ 视觉域 | 剪影/比例/色彩/做旧/磨损 | 枪口制退器什么样式？磨损集中在哪些部位？铭文要不要？ |
| ④ 工程域 | 面数/拓扑/公差/导出/部件拆分 | 部件按可动拆还是按材质拆？公差面留不留？ |
| ⑤ 叙事域 | 语境/陈列/配套（底座/场景/配套件） | 单独陈列还是带场景？要不要弹药/弹壳配件？ |

**深度规则（无限挡专属，覆盖快速档的省问规则）**：
1. **收敛判据 = 域覆盖 + 部件覆盖**，双覆盖完成才可宣布"可以开工"；在此之前 agent
   **不得**提示开工——只有用户说开工才开工（删除 v1.9 的"AI 可提示随时开工"通道）；
2. **部件驱动下沉**：blockout/部件清单成形后，**逐部件一轮**（每轮 4 问 = 4 个部件的
   接口/倒角/纹理/分色）——"严禁重问"指同一字段，**深挖一层不算重问**；
3. **默认值翻牌制**：无限挡内默认值不是"不问的理由"——每个默认值都要被显式确认一次
   （"默认 45cm，确定吗？"）；用户答"确定"记 [确认]，答"你定"记 [agent 决定+理由]；
   （每问仍带默认值，按翻牌制显式确认——不因无限挡而取消默认值机制）；
4. **每轮报告域覆盖进度**：`域覆盖: 物理✓ 功能…进行中 视觉○ 工程○ 叙事○ ｜ 开放点 N`;
5. 快速档/完整档的一切省问规则照旧——本协议**只在无限挡生效**。

【实战验证·坦克建模】无限循环挡规格经真实多轮任务核对：A1 先扫上下文✅ / A2 每轮≤4问带推荐✅ /
A3 全程零重问✅ / A4 卡片 v0→v1→v2 演进✅ / A5"开工"即冻结零追问✅ / A7 退出权持续声明✅
（A6/A8 通道未被用户触发属正常）——与分册规格一致。

### 档位选择项（非直通任务的第一交互）【v1.2.1 增补·用户要求】

分档判据只决定 **AI 推荐哪档**，最终走哪档由用户选——档位是用户的选项，不是 AI 暗自决定：
- 进入澄清阶段时，先亮**四档选择项**（每项一句话说明 + AI 推荐档附一句理由），
  用户选完档再进入对应流程；
- 默认推荐快速档；用户没明确选档 = 接受推荐档（不增加第二往返）；
- 直通档任务仍不打扰：AI 只声明一句"按直通档直接执行，需要多问随时说"；
- 档间升降级规则不变（快速/完整说"继续问"升无限挡；任何档"全按默认，开工"直接执行）。
  **升级跨档直达，不受降档逐级约束**（F-63：升降粒度不对称系有意设计——升级只是加问，降档才涉门配置）；

### 开工提示（问答收口的最后一条消息）【v2.1.8 · 用户反馈 U-02】

问答全部结束（卡片确认 / "按默认开工" / 降档收口）进入执行环时，agent 须先输出一句
**开工提示**，让用户明确知道：问答已结束、接下来是静默执行的建模工作。模板：

> ——问答到此结束 ✅。以下按 **[档位]** 进入真实建模执行：读场景 → 建模（[DETAIL_LEVEL]）
> → 验证 → 渲染。期间以工具调用为主、不再逐问打扰（完整档会在各质量门向您同步产出物或
> checkpoint 图；**无限挡还会请您过目确认后再继续——若希望连续执行，可一开始就说
> "预授权连续"**）；完成后交付 [交付物清单] 与验收宣告行。需要调整随时说，我会停下。

**三要素缺一不可**：①声明问答已结束；②预告静默执行与期间形态（含质量门 checkpoint
出现节奏）；③保留中断权。缺任何一项 = 未完成问答收口。

### 执行契约与质量门【v1.10.6——档位区分的不只是反问强度，更是出品质量；v2.1 专项审计修订】

交互档位选定后，执行侧按本表绑死**最低保证**。门的判据见 13 分册 §2（G1~G4 对应
七阶段关键出口；G0 参考锚定由 R2 的 report 字段承载，不设独立门；DETAIL_LEVEL 只决定
**细节深度上限**——阶段 5 清理与阶段 6 交付恒走，任何档位都不豁免）。
**门的两层语义（F-57 修订，层级依据见 13 §1 表）**：
- **判据标准 = Tier 1，不可降格**——凡执行的门，判据逐项真实通过；产出物可从简
  （低分辨率快渲即可），但结论必须真实，不许互相稀释成印象式自评；
- **门的存在/位置 = 档位配置 + 用户明示偏离**——用户明示赶时间（§6⑥）可降档执行、
  省略门，但被省略的门逐条 `deviation:` 留痕；**跳过必须留痕——静默跳过 = 交付不合格**；
  **G1 铁门禁不可省略**（大形未过关不得做细节；唯一合法出口是 draft 本就不做细节）。

| 档 | 执行前必读 | DETAIL_LEVEL 下限 | 过程门（逐门过） | 出品门 |
|---|---|---|---|---|
| 直通档 | 路由表对应分册（单步修改不走管线，不须 13 分册） | — | — | R1~R6（不适用项标 N/A；纯查询最低限度=R2） |
| 快速档 | **13 分册 §1~§2** + 路由分册 | standard（赶时间可 draft，须声明） | G1 / G2 / G3 / G4 **逐门过**（产出物从简：每门单张低分辨率快渲即可） | R1~R6（R5/R6 按 N/A） |
| 完整档 | **13 分册全文 + 12 分册** + 路由分册 | standard | G1/G2/G3/G4 独立过（每门快渲**或对应机验判据**——G3=体检 report、G4=导出回读，非快渲）；**每门产出物交用户过目**（F-68：与开工提示承诺对齐） | R1~R6（R6 按 N/A） |
| 无限挡 | 完整档全集 | fine（卡片④有预算则从卡片） | 完整档全集（已含每门过目）；另：每门**过目并待用户确认**方可进下一阶段（用户可预授权连续），产出物按 12 分册三级反馈形态呈现 | R1~R6 全项 |

**覆盖面说明**：G 门覆盖几何管线（13 分册七阶段）；材质/构图/灯光阶段的过程验收按
12 分册四阶段 checkpoint 走，交付层由 R5 销项兜底——两套正交，缺一不可。

**出品门清单 R1~R6**（交付宣告逐项列出；**不适用项必须标 N/A，禁止静默省略**）：
- **R1 渲染证据 + 视觉核验（U-03）**：**作为最终渲染证据时**，至少一张最终渲染落盘并
  `bpy.data.images.load` 回读成功（**存在性层**）——**视口截图不算**（SKILL.md §4：视口
  跟着用户视角走，不可复现）。过程层（12 分册 §3 眼快扫）的**固化视角截图**不属 R1 证据，
  亦不得替代之。**视觉层（存在性 ≠ 看过）**：落盘后必须经视觉通道**实际查看图像内容**
  ——用文件读取工具打开渲染 PNG（工具名随客户端：ZCode/Claude Code 为 Read、DSH 为
  read_image），把"看见了什么"（主体可辨认 / 无全黑全白爆曝 / 贴图无平图 / 构图符合
  要求）写进交付说明。**只验证"文件存在+尺寸非零"不构成 R1 完成**——落盘不等于任何人
  看过这张图；预设模型再有多模态能力，像素不进入其视觉上下文就等于瞎——**禁止凭 report 数字想象画面**。**感知前提与降级（F-74）**：视觉层前提 = 运行路由声明图像输入
  且客户端可读图；前提不成立（路由纯文本/读图被拒/视觉桥限流）时**不得假称合格、
  也不得静默跳过**——宣告行标 `R1△(视觉未核验:<原因>)`，交付说明注明"未经视觉核验"
  并建议用户切换图像能力路由后补核验；确认是有图像能力却读不到（链路故障）才走
  SKILL.md §6 恢复 SOP 排障，两种状态要区分；
- **R2 report 实测**：report JSON 含**实际物体名与实测面数**，禁止凭记忆描述场景（铁律 7）；
- **R3 隔离对账**：清理后 `get_scene_info` 物体数回到基线（SKILL.md §5）；
- **R4 跳过留痕**：未走的阶段/门逐条 `deviation:` 声明（13 分册 §6）；无跳过须记
  `R4✓(无偏离)`，不得留空；
- **R5 验收销项**：PRD 卡片 ⑤ 的 Given/When/Then **逐条附 report 证据销项**（完整档起）——
  验收标准在卡片确认时即冻结（外包合同条款惯例），执行中不得私自放宽；
  **视觉类验收条款**（"像参考图/剪影可辨认/无爆曝"等）以 **R1 视觉核验的所见描述**为证据，
  report 数字不构成视觉条款的证据；
  **用户中途变更需求 = 卡片修订并重新确认**（变更走确认闸，不受冻结约束，冻结防的是
  agent 单方面放宽）；
- **R6 假设清零**：卡片⑥逐字段核对，每个"采用默认X"都有翻牌制记录（[确认]/[agent 决定+理由]），
  无未声明的脑补字段（无限挡）。

**交付宣告格式**（最后一条消息必须含此行；不适用的门/项标 N/A，格式本身不得省略）：
`验收: G1✓ G2✓ G3✓(非流形0/零面积0) G4✓ ｜ R1✓(路径;视觉✓) R2✓ R3✓ R4✓(无偏离) R5✓n/n R6✓ ｜ 交付: <文件/图路径>`
（R1 视觉层不可达时按上条标记 △，不得标 ✓；直通档示例：`验收: G1~G4 N/A ｜ R1 N/A(纯查询无渲染产物) R2✓ R3✓ R4✓(无偏离) R5 N/A R6 N/A ｜ 交付: <答复内容>`）
（N/A 一律附短理由——纯"R1 N/A"三字不带理由视为静默省略，等同未完成。）

**敷衍拦截**（四条，对交付质量的机验化把关）：
1. **"完成"的机验定义**：宣告行任何一项缺证据 = 任务未完成。自评"我觉得可以了"**无效**——
   研究结论（Huang et al. 2023；NeurIPS 2024 自我偏袒）：无外部反馈的自纠不可靠且模型偏袒
   自产输出，所以门判据全部机验化（渲染回读/实测数字/清单 diff），不接受印象式自评；
2. **不满意必须归因**：用户表达不满时，把问题映射到具体失败的门/验收条款（"G1 剪影不过
   → 回卡 1 重做 blockout"），禁止无归因的"我再改改"；
3. **同门两连败 → 升级重审卡片**：同一门/条款连续两轮不过，说明 brief 本身有歧义——
   回本分册补问（升档澄清），不许第三轮硬改（外包 QA 升级惯例）；
4. **降档通道**：用户说"快点/别整流程"→ 可降档执行。**档间规则全状态表（F-63 穷举收口）**：

   | 当前档 | 升级（"继续问/多问几轮"） | 降档（"快点/别整流程"） |
   |---|---|---|
   | 直通档 | → 快速档起，用户可选任意更高档 | N/A（非管线档，无门可省） |
   | 快速档 | → 无限挡（**跨档直达**） | **管线任务禁降至直通档**（见下）；= 快速档 + DETAIL_LEVEL=draft + 产出物从简 |
   | 完整档 | → 无限挡（**跨档直达**） | → 快速档 |
   | 无限挡 | N/A（已最高；退出权 = 说"开工"） | → 完整档（用户可再指定继续降至快速档） |

   **升级跨档直达、降档逐级**——不对称系有意设计：升级只是加问，降档才涉门配置。
   **管线任务不得降至直通档**（F-64：任务类型中立的表述——管线任务 = 走 13 分册几何
   管线或 12 分册四阶段 checkpoint 任一；非建模任务如全场景材质布光降入直通档同样会
   跳过 checkpoint，后果与建模任务跳过 13 分册管线同构）。被省略的门 
   `deviation:` 留痕（G1 不可省略），宣告行仍须完整列出、其中 R1~R4 底线**永不静默省略**
   （允许 N/A，但 N/A 须附理由、不得省略整行）并注明"应用户要求降档"。
   **DETAIL_LEVEL 联动（第四维；F-65 补双向+时点）**：
   - **降档**：DETAIL_LEVEL 不随降档自动下调（其为下限参数、由骨架①设定）；用户可
     显式调低（如"快速档 + draft"），须照常声明；
   - **升级**：**不得低于目标档下限**——升至无限挡须 ≥fine（或按卡片④预算裁并声明）；
     "绑死最低保证"原则对升级方向同样适用；
   - **时点**：澄清阶段升降 = 按新档配额与卡片流程继续；执行中升级 = 剩余工作按新档
     门配置与 DETAIL_LEVEL 下限抬升（已完成部分不追溯重做）；执行中降档 = 剩余工作
     省略门、R4 留痕。
   **收工三问（交付宣告后顺手自检，全档适用；细则见 13 分册 §8 收工清单）**：
   ①本次是否有可复用组件值得提升入 fragments/？②过程是否构成 worked example 值得
   整理入 docs/？③实战踩坑是否已回填 ERR 表/分册？

### 防盘问补充规则（每问必过）

追错澄清（用户指出错误）不计入新配额；用户说"随便/你定/直接做"立即终止提问按默认执行；
缺口多于配额时按"影响交付物大 × 不确定度高"排序取前 4。

## 2. 好反问问题判据（每问必过）

1. **可答案化**：2~5 个互斥选项 或 ≤5 词短答；禁裸开放题；
2. **带推荐**：标注"推荐：X + 一句理由"；数值问题给带量纲默认值（"座面高多少？默认 45cm"）；
3. **影响交付物才问**：会改变形态/外观/出图/格式才问；纯执行细节（用哪个修改器）不问；
4. **信息增益 > 打断成本**：猜错便宜且可逆的（背景色）直接默认值；猜错贵的（尺寸/风格/
   输出用途）必须问；
5. **非复合非引导**：一次一个主题；选项中性并列，倾向靠"推荐"标签表达而非措辞。

## 3. 分型问题池（每型取影响最大的 3~4 问进快速档）

### A 建模单件（椅子/桌子/道具）
- 最终用途：渲图看效果 / 进游戏引擎 / 3D 打印？（默认：渲图展示——用途决定一切下游规格）
- 真实尺寸：有要求吗？（默认：椅子座高 45cm 总高 90cm；桌子高 75cm）
- 风格锚点：参考图或关键词？（默认：现代简约；有图则参考图即直通档信号）
- 面数预算：要控制吗？（默认：渲图不设限；游戏 prop 1k~10k tris）
- 是否 game-ready：要 UV/贴图吗？（默认：只要形状）
- 来源优先：先搜素材库还是全新建？（默认：先搜 PolyHaven/PolyPizza，没有再手建）
  **问答前先 `get_addon_status` 探集成开关并把五库开/关状态报给用户**（不得静默消费，
  v2.1.7）；要用的库未开启时指引导在 N 面板勾选（即时生效）。

### B 场景搭建
- 场景类型与情绪：什么场景什么氛围？（**此项不可默认，必答**）
- 空间尺寸：大概多大？（默认：4m×5m×2.8m 标准房间）
- 资产来源：免费素材库拼还是全程序化？启用哪些集成库？（默认：库优先 CC0；
  **五库默认全关**——问答前先 `get_addon_status` 探开关并报状态给用户，不得静默消费）
- 细节密度：背景物件多细？（默认：中景精细、远景低模占位）
- 相机灯光：顺带配吗？（默认：50mm 相机 + HDRI 环境光）

### C 材质灯光
- 写实 vs 风格化？（默认：写实）
- 贴图/HDRI 来源：启用哪些集成库？（默认：PolyHaven 优先——贴图/HDRI 主力且免密钥；
  **问答前先 `get_addon_status` 探开关并报状态给用户，不得静默消费**）
- 贴图分辨率？（默认：2K，特写件 4K）
- 贴图通道：PBR 全套还是基础色？（默认：Principled 全套）
- 光线氛围：日光/夜景/影棚三点光？（默认：日光 HDRI）
- 色板：有指定配色吗？（默认：跟随参考图或中性灰底）

### D 渲染出图
- 用途渠道：电商白底/社媒/打印？（**必答优先级最高**——决定分辨率与背景）
- 角度张数：几个视角？（默认：1 张主视角；电商 3 角度正/侧/45°）
- 背景与地板？（默认：电商纯白无缝；氛围图简单环境）
- 分辨率？（默认：1920×1080；电商 2000×2000 方图）
- 文件格式？（默认：PNG；透明底需求则 RGBA PNG）
- 引擎：Cycles 写实还是 EEVEE 快速？（默认：预览 EEVEE、终图 Cycles）

### E 动画
- 时长与帧率？（默认：5 秒 @ 24fps）
- 运镜：环绕/推进/固定？（默认：360° 环绕一圈）
- 需要无缝循环吗？（默认：不需要）
- 出 MP4 还是序列帧？（默认：MP4 H.264）
- **交付核验（U-03 同族）**：序列帧/转台产出后须用**文件读取工具抽查首/中/尾帧实看**（运动是否符合运镜设计、循环首尾是否衔接），动画质量判断禁止凭 keyframe 数字想象；视觉通道不可达时按 00 分册 R1 降级条款标 △（F-93 补出口）。

### F 导出交付
- 格式？（默认：glTF 单文件内嵌；进 UE 则 FBX）
- 命名规范？（默认：snake_case + 语义前缀 + 无中文）
- 需要 LOD 吗？（默认：不需要，除非进引擎）
- 目标引擎的单位/上方向？（默认：米制，glTF 自动 Y-up）

### G 改既有场景
- 改动范围：只改指定对象，还是周围可顺手调？（默认：**只改指定对象，其余一律不碰**）
- 先出场景体检报告再动手吗？（默认：先只读审计再确认方案）
- 改完要保存 .blend 吗？（默认：**绝不自动保存**，需明确要求）
- 改动量大时先给方案确认还是直接改？（默认：方案确认后执行）

## 4. PRD 卡片模板（确认后 = 骨架参数区，12 分册 §6）

```
[BMCP-PRD] 任务ID / 日期 / 分型(A~G)
① 目标一句话 + 对标参考（图/链接；**有参考图必须实看并把视觉规格摘录进卡片**——剪影/
   配色/材质性格/氛围，实看义务与提取清单见 14 分册 §2）
② 交付物清单（网格?材质?渲染图?导出文件?）——量化写死：分辨率/格式/路径
③ 非目标（本次不做什么）
④ 技术约束：引擎、单位、面数预算、PREFIX 与集合纪律
⑤ 验收标准 Given/When/Then（全部可机验，挂钩 report 字段与快渲判据）
⑥ 边界与假设：未答字段在此写"采用默认X"（显式假设，不脑补）
⑦ 反查雷区 3 条（执行完逐条销雷）
```
- **落盘规则【已裁定③】**：快速档只在对话展示；完整档自动存 %TEMP% 并报路径；
  用户工程目录仅用户开口才写。
- 问题语言【已裁定②】：跟随用户最近一条消息；专有名词保留英文。

## 5. 示例

**例 1（快速档收口）**——用户："帮我做个椅子"
→ 反问批（4 问带推荐）：①用途？推荐渲图展示 ②尺寸？推荐座高 45cm ③风格？推荐现代简约，
有参考图吗 ④要材质吗？推荐基础 PBR 无贴图
→ 用户："都按推荐" → 卡片（⑥区写明假设）→ 确认 → 骨架参数区 → 执行环。

**例 2（无限循环挡收敛）**——用户："布置一个房间，我们慢慢聊"
→ 每轮 4 问逐层细化（类型情绪→家具清单→材质灯光→构图出图），卡片每轮演进；
→ 第 4 轮用户："就这样，开工" → 冻结卡片 → 参数区 → 执行环，零追问。
